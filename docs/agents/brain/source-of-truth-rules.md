# Source precedence and public claims

Follow current user requirements and amendments, then applicable repository
instructions. Prove current behavior from source and executable tests. Official
MCP/Registry specifications define wire semantics; DockPipe source defines its
actual installation/lifecycle contracts. Cloud workflow files define the chosen
development organization. Historical memory and proposed architecture are leads,
not proof. Resolve conflicts explicitly and preserve tested-versus-pending status.

The registry amendment supersedes the original dedicated DockPipe store package:
one standalone FreeFlight distribution, no duplicate DockPipe-specific build.
Registry is discovery metadata; GitHub Releases host qualified artifacts.
Never publish private DockPipe Cloud, Nucleon or Pipelang implementation details.
Never copy proprietary Glider/TGlider code or imply affiliation. Public capability
documentation can guide prioritization only. Link only verified destinations.

A file existing is not evidence that it built, passed tests, deployed or published.
Record exact commands, platform, failures and artifacts; do not silently upgrade
fixture correctness to full project support or cross-platform readiness.
