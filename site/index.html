01 / INSTALLATION

Your tools. Your workflow.

FreeFlight is designed to run independently, or as one package inside DockPipe.

Development preview

No tested production release or published DockPipe package is announced here. Follow the repository for verified artifacts and platform availability. Do not treat source builds as production installers.

A

Standalone

The release goal is a platform-specific native executable with its language workers supplied together. End users will not need DockPipe.

Until verified binaries are available, use the repository’s native CMake build instructions and documented worker prerequisites.

B

With DockPipe

FreeFlight targets the existing DockPipe store as a single freeflight package classified as mcp.

Store publication and gateway integration remain release gates. Installation commands will be documented alongside a verified package.

04 / MCP CONFIGURATION

One endpoint. Less setup.

FreeFlight starts with MCP over stdio. The client launches the native server; language workers are internal to the application.

Connect a client

Configure your client with the absolute path to the installed FreeFlight executable and explicitly authorize the workspace you intend to inspect. Use the repository’s exact arguments for your build.

Codex and other MCP clients have different configuration formats. Follow the maintained examples before launching.

View current MCP examples ↗

Keep control of your workspace

Read-only navigation is the default. Editing tools must be explicitly invoked, validate workspace boundaries and protect against concurrent file changes.

Project evaluation and language tooling can carry execution risks. Read the documented trust boundaries before opening an unfamiliar repository.

SOURCE BUILD / DEVELOPMENT SETUP

Connect with an explicit configuration

This example is for a local source build. Replace every absolute path with a real path on your machine. Worker runtimes must currently be provisioned by the developer; this is not a bundled release installation.

Codex MCP configuration

[mcp_servers.freeflight]
command = "/absolute/path/to/freeflight"
args = ["--config", "/absolute/freeflight.json"]

JSON-based MCP clients

{
  "mcpServers": {
    "freeflight": {
      "command": "/absolute/path/to/freeflight",
      "args": ["--config", "/absolute/freeflight.json"]
    }
  }
}

Development server configuration: freeflight.json

{
  "roots": ["/absolute/workspace"],
  "engines": {
    "typescript": ["/absolute/node", "/absolute/worker.mjs"],
    "javascript": ["/absolute/node", "/absolute/worker.mjs"],
    "csharp": ["/absolute/dotnet", "/absolute/worker.dll"]
  }
}

Both clients launch the same native stdio server. Only authorize workspace roots you intend to expose. Consult repository documentation for worker build locations, runtime prerequisites and current platform limitations.
